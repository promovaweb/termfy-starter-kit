Documentação do Termfy

termfy é um executável único com três modos de uso:

Modo Como entrar Para quem
TUI termfy sem argumentos em um terminal interativo pessoas
CLI termfy <command> [options], com saída em texto ou --json pessoas, scripts e agentes
MCP termfy mcp, servidor Model Context Protocol via stdio agentes de IA

Os três modos compartilham a mesma identidade (src/app/manifest.ts), a mesma configuração (~/.termfy/settings.json), o mesmo cofre de credenciais (~/.termfy/credentials.json, cifrado) e a mesma tabela de exit codes.

Mapa

  • cli.md: commands, opções globais, convenções de saída e a referência gerada do registry.
  • tui.md: abas, teclas, tema e como criar uma screen.
  • mcp.md: tools, resources, prompts e configuração nos clientes.
  • configuration.md: settings.json, credentials.json, master key e variáveis de ambiente.
  • exit-codes.md: tabela de exit codes e como tratá-los.
  • architecture.md: pastas, camadas e fluxo de execução.
  • customize-template.md: usar este repositório como ponto de partida de um novo binário.
  • release.md: versão, changelog, tag, GitHub Release e binários.
  • opencli.json: descrição OpenCLI gerada por bun run opencli.

Documentação embutida

Toda esta pasta entra no binário. Um agente pode ler tudo sem acesso ao repositório:

termfy --skill          # tudo
termfy --skill cli      # só a seção do CLI, com a referência gerada
termfy --skill mcp --json

Os tópicos aceitos são cli, tui, mcp, config e exit-codes.

Idioma

O código, os nomes de commands, options, keys de configuração, campos do --json e as mensagens do binário são em inglês. Esta documentação e as skills do framework são em português do Brasil, com os termos técnicos preservados em inglês.

CLI

Convenções

  • termfy <command> [subcommand] [arguments] [options].
  • Options aceitam --key value e --key=value. Não há agrupamento de flags curtas (-abc).
  • -- encerra a leitura de options; o que vem depois é argument.
  • Options globais valem em qualquer posição, antes ou depois do command.
  • Sem argumentos, em terminal interativo, o binário abre a TUI. Sem TTY, imprime o help e sai com exit code 2.
  • Toda saída de dados vai para stdout. Avisos, progresso e erros em modo texto vão para stderr.
  • Nomes de commands, subcommands, options, arguments, keys e campos de saída são em inglês. Mensagens do binário também.

Options globais

Option Efeito
-h, --help Help do command atual. Exit code 0.
-V, --version Imprime termfy <version>. Exit code 0.
--json Saída em JSON com envelope estável. Erros também saem em JSON, em stdout.
--skill [topic] Documentação embutida. Topics: cli, tui, mcp, config, exit-codes.
--opencli Descrição OpenCLI 0.1 da árvore de commands em JSON.
--no-color Desliga cores ANSI. NO_COLOR=1 tem o mesmo efeito.

Saída em texto e em JSON

Texto é o padrão quando output.format em settings.json é text. Com --json, ou com output.format = json, a saída segue este envelope:

{ "ok": true, "command": "termfy config get", "data": { "key": "tui.theme", "value": "night" } }

Em erro:

{
  "ok": false,
  "command": "termfy credentials get",
  "error": { "code": 4, "name": "CREDENTIALS", "message": "Credential \"x\" not found.", "details": { "name": "x" } }
}

O exit code do processo é sempre o mesmo de error.code. Um agente deve ler os dois: o envelope para a mensagem, o code para a classe da falha.

Commands do esqueleto

Command Função
tui [--tab <tab>] Abre a TUI. Exige TTY.
about Version, executable, runtime, platform e credits.
config list\|get\|set\|unset\|path\|schema Preferências em settings.json.
credentials set\|get\|list\|remove\|status\|clear Cofre cifrado em credentials.json.
mcp [--list] Servidor MCP via stdio, ou listagem do que ele registra.
skill [topic] Mesmo efeito de --skill.

Como adicionar um command

  1. Copie template/command/example.ts para src/cli/commands/<name>.ts.
  2. Preencha name, description, arguments, options, examples e exitCodes. Toda option precisa de description; é ela que aparece no --help, no --skill e no OpenCLI.
  3. Implemente run(ctx) devolvendo { data, text }. data é o que sai em --json; text é o que sai para humanos. Lance AppError (ou use error.*) para falhas previstas, com o exit code certo.
  4. Registre o command em src/cli/commands.ts.
  5. Rode bun test, bun run opencli e confira docs/opencli.json.

Segredos nunca entram por argument de linha de comando. Leia pelo stdin ou por readSecret(); grave com setCredential(); recupere com getCredential(), que encerra com exit code 4 quando o valor não existe.

TUI

A interface de terminal abre com termfy sem argumentos ou com termfy tui. Ela exige stdin e stdout em um TTY; fora disso o processo encerra com exit code 8.

Abas

Aba Conteúdo
Overview Environment (binary, runtime, platform, terminal, data directory), estado de settings.json e do cofre, settings em vigor e next steps.
About Binary, project, license, credits e standards seguidos.

A aba inicial vem de tui.initialTab em settings.json ou de --tab.

Teclas

Tecla Ação
← → [ ] aba anterior ou seguinte
Tab próxima aba
1 … 9 ir para a aba de mesmo número
? mostrar ou esconder o help de teclas
q Esc Ctrl+C sair

Cada screen pode declarar teclas próprias em keys e tratá-las em onKey. Elas aparecem na barra inferior antes das teclas globais.

Tema

Duas paletas em src/tui/theme.ts: night (padrão) e day. A escolha vem de tui.theme. As cores têm nomes de papel (accent, textDim, border), não de matiz, para que uma troca de paleta não exija tocar nas screens.

Princípios do visual, no estilo modern unix:

  • bordas arredondadas com título na própria borda;
  • rótulos apagados à esquerda e valores em cor plena à direita;
  • uma cor de accent para o que está ativo, uma secundária para links e origens externas; verde, âmbar e vermelho só para estado;
  • barra de status com teclas em blocos invertidos;
  • sem espaços vazios entre painéis vizinhos; padding interno de uma célula;
  • nada pisca, nada rola sozinho.

Como criar uma screen

  1. Copie template/screen/example.ts para src/tui/screens/<id>.ts.
  2. Preencha id, title, description e mount(ctx). Use os componentes de src/tui/components.ts (panel, keyValueTable, list, heading, dim) e as cores de ctx.theme.
  3. Se a screen precisar de atualização periódica, inicie o timer em onEnter e limpe em onLeave.
  4. Registre em src/tui/screens/index.ts. A ordem da lista é a ordem das abas.
  5. Se o id for uma opção válida de aba inicial, acrescente-o em tui.initialTab (src/config/settings.ts) e em --tab (src/cli/commands/tui.ts).

A TUI roda sobre o OpenTUI (@opentui/core). Use BoxRenderable, TextRenderable, TabSelectRenderable, ScrollBoxRenderable e os demais renderables do pacote. Sempre devolva o terminal com renderer.destroy(); mountTui() já cuida disso para q, Esc e Ctrl+C.

Testar sem terminal

tests/tui.test.ts monta a interface com createTestRenderer de @opentui/core/testing, pressiona teclas com mockInput.pressKey e confere o frame com captureCharFrame. mountTui aceita qualquer renderer; startTui cria o renderer real.

MCP

termfy mcp transforma o processo em um servidor Model Context Protocol sobre stdio. Nada mais é escrito em stdout; diagnósticos vão para stderr.

Configuração no cliente

{
  "mcpServers": {
    "termfy": { "command": "termfy", "args": ["mcp"] }
  }
}

Para o Claude Code: claude mcp add termfy -- termfy mcp. Para desenvolvimento, sem compilar: "command": "bun", "args": ["run", "src/main.ts", "mcp"].

Tools

Tool Entrada Saída
about nenhuma identity, runtime, platform, data directory e credits
exit_codes nenhuma tabela de exit codes
skill topic? (cli, tui, mcp, config, exit-codes) documentação em Markdown
config_list nenhuma keys de settings.json em vigor e o schema
config_get key valor da key; isError quando não existe
credentials_status nenhuma file, master key source, count e names

Nenhuma tool devolve o valor de uma credencial, e nenhuma tool grava. Escrita continua no CLI, onde há confirmação humana.

Resources

URI Conteúdo
termfy://about identity em JSON
termfy://exit-codes exit codes em JSON
termfy://skill documentação completa em Markdown
termfy://skill/{topic} uma seção; o template lista os topics

Prompts

Prompt Arguments Função
operate task instrui o agente a ler skill cli e executar a task pelo CLI com --json

Listar sem iniciar

termfy mcp --list
termfy mcp --list --json

Testar

npx @modelcontextprotocol/inspector termfy mcp

O Inspector abre uma página local para chamar tools, ler resources e inspecionar as mensagens JSON-RPC.

Como adicionar uma tool

  1. Copie template/tool/example.ts para src/mcp/tools/<name>.ts.
  2. Declare inputSchema com Zod e descreva cada campo com .describe(). A description da tool diz quando usar e o que ela devolve.
  3. Devolva content em texto e, quando a saída for estruturada, structuredContent com o mesmo objeto.
  4. Acrescente a tool ao catalog.tools para que mcp --list a enxergue.
  5. Registre a função em registerAll em src/mcp/server.ts.
  6. Teste com o Inspector e com bun test.

Nomes de tools usam snake_case. Tools que gravam ou chamam APIs externas precisam dizer isso na description e nunca devem ecoar segredos na resposta.

Configuração e credenciais

Tudo que o binário persiste fica em ~/.termfy/:

Arquivo Conteúdo Permissão
settings.json preferências em texto claro 0600
credentials.json envelope AES-256-GCM com os segredos 0600
master.key master key em hexadecimal, criada na primeira gravação 0600

A pasta é criada com 0700. A variável TERMFY_HOME troca a raiz, útil em testes e CI.

settings.json

Keys em notação de ponto. O schema do esqueleto:

Key Tipo Padrão Função
output.format text ou json text formato padrão da saída do CLI
output.colors boolean true cores ANSI na saída de texto
tui.initialTab overview ou about overview aba aberta ao iniciar a TUI
tui.theme night ou day night paleta da TUI
telemetry.enabled boolean false reservado para projetos derivados

Commands:

termfy config list
termfy config get tui.theme
termfy config set output.format json
termfy config unset telemetry.enabled
termfy config path
termfy config schema

Keys fora do schema são aceitas como texto. Para que uma key nova ganhe tipo, padrão e documentação, acrescente-a a SETTINGS_SCHEMA em src/config/settings.ts.

credentials.json

O arquivo guarda um envelope:

{ "version": 1, "algorithm": "aes-256-gcm", "iv": "<base64>", "tag": "<base64>", "data": "<base64>" }

data é o JSON { "name": "value" } cifrado. Names seguem [a-z0-9][a-z0-9_.-]{0,63}, por exemplo openai.api_key ou github.token.

A master key tem 32 bytes e vem, nesta ordem:

  1. da variável TERMFY_MASTER_KEY (64 caracteres hexadecimais);
  2. do arquivo master.key, gerado automaticamente.

Gere uma chave para a variável com openssl rand -hex 32. Quando a variável está definida, master.key é ignorado.

Commands:

termfy credentials set openai.api_key            # digita sem eco
printf '%s' "$TOKEN" | termfy credentials set github.token --stdin
termfy credentials get openai.api_key            # mascarado
termfy credentials get openai.api_key --reveal   # em claro
termfy credentials list
termfy credentials remove github.token
termfy credentials status
termfy credentials clear --yes

O que a cifra protege

A cifra protege o arquivo contra leitura casual, cópia em backup e varredura do disco por outras ferramentas. Quem tem acesso à mesma conta do sistema consegue ler master.key e decifrar o conteúdo. Para um nível acima, injete a chave por TERMFY_MASTER_KEY a partir de um gerenciador de segredos e não grave master.key em disco.

Usar uma credencial no código

import { getCredential } from "../config/credentials.ts";

const token = getCredential("github.token"); // lança AppError(4) quando não existe

Nunca escreva o valor em log, em erro, em data do --json nem em resposta de tool MCP.

Variáveis de ambiente

Variável Efeito
TERMFY_HOME troca ~/.termfy/ por outra pasta
TERMFY_MASTER_KEY master key em hex; dispensa master.key
NO_COLOR desliga cores na saída de texto

Exit codes

Zero é sucesso. Cada família de falha tem um número fixo. Scripts e agentes devem tratar o code antes de interpretar a mensagem.

Code Name Quando
0 SUCCESS operação concluída
1 GENERIC_ERROR falha inesperada sem classificação
2 USAGE arguments, options ou subcommand inválidos; também quando o binário roda sem argumentos fora de um TTY
3 CONFIG settings.json ausente, inválido ou key desconhecida
4 CREDENTIALS credentials.json ilegível, master key ausente ou credencial não encontrada
5 NETWORK_OR_API falha de rede ou resposta de API fora do esperado
6 NOT_FOUND recurso solicitado não existe
7 PERMISSION permissão negada no sistema de arquivos
8 NO_TTY a TUI exige um terminal interativo
9 MCP o servidor MCP falhou ao iniciar ou perdeu o transporte
130 INTERRUPTED entrada cancelada ou processo interrompido com Ctrl+C

A fonte única é src/app/exit-codes.ts. A mesma tabela aparece em --help, em --opencli, na tool MCP exit_codes e na resource termfy://exit-codes.

Em shell

if ! termfy credentials get github.token --json > /tmp/out.json; then
  case $? in
    4) echo "save the credential with: termfy credentials set github.token" ;;
    *) echo "failed: see /tmp/out.json" ;;
  esac
fi

No código

import { error } from "../app/errors.ts";

throw error.network("The API responded 503.", { status: 503 }); // exits with 5

Para uma família nova, acrescente a constante e a description em src/app/exit-codes.ts e um atalho em src/app/errors.ts. Não reutilize números.

Fluxo de execução

  1. main.ts lê argv. Sem argumentos e com TTY, chama runCli(["tui"]). Sem TTY, imprime o help e sai com 2. Com argumentos, passa adiante.
  2. parser.ts caminha pela árvore do registry, separa options e arguments e valida contra as definições. Falhas viram AppError(2).
  3. index.ts trata --version, --opencli, --skill e --help. Depois chama run(ctx) do command.
  4. O command devolve { data, text }. index.ts imprime texto ou o envelope JSON e devolve o exit code.
  5. main.ts encerra o processo com esse code.

mcp e tui são commands como os demais; eles só não devolvem antes de o transporte ou o renderer fechar.

Regras de dependência

  • app/ não importa de nenhuma outra camada.
  • config/ importa só de app/.
  • cli/, mcp/ e tui/ importam de app/ e config/. mcp/ e tui/ podem reutilizar funções de cli/commands/* que coletam dados (como aboutData), nunca o contrário.
  • skill/ importa de cli/registry.ts para gerar a referência.

Idioma do código

Todo o código é em inglês: nomes de arquivos, identificadores, comentários, mensagens do binário, commands, options, keys e campos do --json. A documentação em docs/, o README.md, o AGENTS.md e as skills são em português do Brasil com os termos técnicos em inglês.

Build

bun run build compila src/main.ts em dist/<bin> para a plataforma atual com bun build --compile. bun run build:all gera linux-x64, linux-arm64, darwin-x64, darwin-arm64 e windows-x64. O OpenTUI embute a biblioteca nativa no executável; o docs/ entra como texto; o package.json entra como JSON.

Personalizar o template

Este repositório é um template do GitHub. Para iniciar um binário novo:

  1. No GitHub, clique em Use this template e crie o repositório.

  2. Clone, instale e renomeie:

    bun install
bun run init -- --name mycli --title "My CLI" --description "What it does." --author "Your company" --repository https://github.com/org/mycli --site https://example.com

    O script reescreve package.json (name, bin, description, bloco termfy), .env.example e as menções a termfy em README.md, AGENTS.md, CHANGELOG.md e .github/workflows/. Os placeholders termfy em docs/ são resolvidos em tempo de execução pelo manifest, então docs/ não precisa de edição.

  3. Escreva o CLISPEC.md com a skill termfy-spec: ela entrevista você e registra propósito, commands, options, saídas, screens, tools e keys de configuração. As demais skills leem esse arquivo antes de implementar.

  4. Confira: bun run dev -- --version, bun run dev -- --help, bun run dev.

  5. Rode bun run ebook para regenerar o guia em PDF e EPUB com o título novo.

  6. Rode bun run validate.

  7. Apague a seção “Sobre o template” do README e escreva a do produto.

  8. Faça o primeiro commit e a primeira release conforme release.md.

Quer Onde

nova aba template/screen/example.ts → src/tui/screens/, registrar em src/tui/screens/index.ts
nova tool MCP template/tool/example.ts → src/mcp/tools/, registrar em src/mcp/server.ts

Skills

As skills do framework promovaweb/termfy estão instaladas em .agents/skills/ e registradas em skills-lock.json. Elas ensinam um agente a evoluir o projeto:

Skill Uso
termfy-spec entrevistar a pessoa e montar o CLISPEC.md
termfy-init criar o binário a partir do template e fazer o primeiro commit
termfy-cli commands, options, saída texto/JSON, exit codes e OpenCLI
termfy-tui screens, componentes, tema e o visual modern unix
termfy-mcp tools, resources, prompts e testes com o Inspector
termfy-config settings, credenciais, master key e variáveis

Atualize para a versão mais recente do framework com bun run skills:update. Se a pasta sumir, reinstale com bun run skills:install. Não edite as skills aqui: mudanças acontecem no framework. Dentro deste repositório, os agentes leem AGENTS.md, que aponta para elas.

Release

Toda alteração publicada sai com versão, changelog, tag e GitHub Release.

  1. Atualize version em package.json (SemVer).
  2. Registre a mudança em CHANGELOG.md, no formato Keep a Changelog.
  3. Se docs/ mudou, avance ebook/VERSION e rode bun run ebook. O PDF e o EPUB em ebook/ entram no commit.
  4. Rode bun run validate.
  5. Commit: release: <bin> vX.Y.Z.
  6. Tag: git tag vX.Y.Z.
  7. Push: git push origin main --tags.
  8. O workflow release.yml compila os binários para linux-x64, linux-arm64, darwin-x64, darwin-arm64 e windows-x64, gera SHA256SUMS e publica a GitHub Release com as notas do changelog, o PDF e o EPUB do guia.
  9. Confira a release em https://github.com/<org>/<repo>/releases/tag/vX.Y.Z.

Uma tag publicada nunca é movida. Correção posterior recebe nova versão.

Build local

bun run build          # dist/<bin> para a plataforma atual
bun run build:all      # dist/<bin>-<platform> para todas
./dist/<bin> --version

Ebook do guia

bun run ebook          # ebook/<Title>-User-Guide-v<version>.{pdf,epub}
bun run ebook:verify   # confere sem gerar; entra em bun run validate

A fonte é a própria docs/, com os placeholders resolvidos pelo manifest. Depois de bun run init, regenere o ebook para a capa e o rodapé levarem o título novo. Requer Pandoc, WeasyPrint, ImageMagick, xmllint, poppler-utils e unzip.
