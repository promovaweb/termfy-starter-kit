Documentação do Termfy

termfy é um executável único com três modos de uso:

Modo Como entrar Para quem
TUI termfy sem argumentos em um terminal interativo pessoas
CLI termfy <comando> [opções], com saída em texto ou --json pessoas, scripts e agentes
MCP termfy mcp, servidor Model Context Protocol via stdio agentes de IA

Os três modos compartilham a mesma identidade (src/app/manifesto.ts), a mesma configuração (~/.termfy/settings.json), o mesmo cofre de credenciais (~/.termfy/credentials.json, cifrado) e a mesma tabela de códigos de saída.

Mapa

  • cli.md: comandos, opções globais, convenções de saída e a referência gerada do registro.
  • tui.md: abas, teclas, tema e como criar uma tela.
  • mcp.md: tools, resources, prompts e configuração nos clientes.
  • configuracao.md: settings.json, credentials.json, chave mestra e variáveis de ambiente.
  • codigos-de-saida.md: tabela de códigos e como tratá-los.
  • arquitetura.md: pastas, camadas e fluxo de execução.
  • personalizar-template.md: usar este repositório como ponto de partida de um novo binário.
  • release.md: versão, changelog, tag, GitHub Release e binários.
  • opencli.json: descrição OpenCLI gerada por bun run opencli.

Documentação embutida

Toda esta pasta entra no binário. Um agente pode ler tudo sem acesso ao repositório:

termfy --skill          # tudo
termfy --skill cli      # só a seção do CLI, com a referência gerada
termfy --skill mcp --json

Os tópicos aceitos são cli, tui, mcp, config e codigos.

CLI

Convenções

  • termfy <comando> [subcomando] [argumentos] [opções].
  • Opções aceitam --chave valor e --chave=valor. Não há agrupamento de flags curtas (-abc).
  • -- encerra a leitura de opções; o que vem depois é argumento.
  • Opções globais valem em qualquer posição, antes ou depois do comando.
  • Sem argumentos, em terminal interativo, o binário abre a TUI. Sem TTY, imprime a ajuda e sai com código 2.
  • Toda saída de dados vai para stdout. Avisos, progresso e erros em modo texto vão para stderr.

Opções globais

Opção Efeito
-h, --help Ajuda do comando atual. Código 0.
-V, --version Imprime termfy <versão>. Código 0.
--json Saída em JSON com envelope estável. Erros também saem em JSON, em stdout.
--skill [topico] Documentação embutida. Tópicos: cli, tui, mcp, config, codigos.
--opencli Descrição OpenCLI 0.1 da árvore de comandos em JSON.
--no-color Desliga cores ANSI. NO_COLOR=1 tem o mesmo efeito.

Saída em texto e em JSON

Texto é o padrão quando saida.formato em settings.json é texto. Com --json, ou com saida.formato = json, a saída segue este envelope:

{ "ok": true, "comando": "termfy config get", "dados": { "chave": "tui.tema", "valor": "noite" } }

Em erro:

{
  "ok": false,
  "comando": "termfy credentials get",
  "erro": { "codigo": 4, "nome": "CREDENCIAIS", "mensagem": "Credencial \"x\" não encontrada.", "detalhes": { "nome": "x" } }
}

O código de saída do processo é sempre o mesmo de erro.codigo. Um agente deve ler os dois: o envelope para a mensagem, o código para a classe da falha.

Comandos do esqueleto

Comando Função
tui [--aba <aba>] Abre a TUI. Exige TTY.
about Versão, executável, runtime, plataforma e créditos.
config list\|get\|set\|unset\|path\|schema Preferências em settings.json.
credentials set\|get\|list\|remove\|status\|clear Cofre cifrado em credentials.json.
mcp [--list] Servidor MCP via stdio, ou listagem do que ele registra.
skill [topico] Mesmo efeito de --skill.

Como adicionar um comando

  1. Copie template/comando/exemplo.ts para src/cli/comandos/<nome>.ts.
  2. Preencha nome, descricao, argumentos, opcoes, exemplos e codigosSaida. Toda opção precisa de descricao; é ela que aparece no --help, no --skill e no OpenCLI.
  3. Implemente executar(ctx) devolvendo { dados, texto }. dados é o que sai em --json; texto é o que sai para humanos. Lance ErroApp (ou use erro.*) para falhas previstas, com o código certo.
  4. Registre o comando em src/cli/comandos.ts.
  5. Rode bun test, bun run opencli e confira docs/opencli.json.

Segredos nunca entram por argumento de linha de comando. Leia pelo stdin ou por lerSegredo(); grave com definirCredencial(); recupere com obterCredencial(), que encerra com código 4 quando o valor não existe.

TUI

A interface de terminal abre com termfy sem argumentos ou com termfy tui. Ela exige stdin e stdout em um TTY; fora disso o processo encerra com código 8.

Abas

Aba Conteúdo
Overview Ambiente (binário, runtime, plataforma, terminal, pasta de dados), estado de settings.json e do cofre, configuração em vigor e próximos passos.
About Binário, projeto, licença, créditos e padrões seguidos.

A aba inicial vem de tui.abaInicial em settings.json ou de --aba.

Teclas

Tecla Ação
← → [ ] aba anterior ou seguinte
Tab próxima aba
1 … 9 ir para a aba de mesmo número
? mostrar ou esconder a ajuda de teclas
q Esc Ctrl+C sair

Cada tela pode declarar teclas próprias em teclas e tratá-las em aoTecla. Elas aparecem na barra inferior antes das teclas globais.

Tema

Duas paletas em src/tui/tema.ts: noite (padrão) e dia. A escolha vem de tui.tema. As cores têm nomes de papel (acento, textoSutil, borda), não de matiz, para que uma troca de paleta não exija tocar nas telas.

Princípios do visual, no estilo modern unix:

  • bordas arredondadas com título na própria borda;
  • rótulos apagados à esquerda e valores em cor plena à direita;
  • uma cor de acento para o que está ativo, uma secundária para links e origens externas; verde, âmbar e vermelho só para estado;
  • barra de status com teclas em blocos invertidos;
  • sem espaços vazios entre painéis vizinhos; padding interno de uma célula;
  • nada pisca, nada rola sozinho.

Como criar uma tela

  1. Copie template/tela/exemplo.ts para src/tui/telas/<id>.ts.
  2. Preencha id, titulo, descricao e montar(ctx). Use os componentes de src/tui/componentes.ts (painel, tabelaChaveValor, lista, titulo, sutil) e as cores de ctx.tema.
  3. Se a tela precisar de atualização periódica, inicie o timer em aoEntrar e limpe em aoSair.
  4. Registre em src/tui/telas/index.ts. A ordem da lista é a ordem das abas.
  5. Se o id for uma opção válida de aba inicial, acrescente-o em tui.abaInicial (src/config/settings.ts) e em --aba (src/cli/comandos/tui.ts).

A TUI roda sobre o OpenTUI (@opentui/core). Use BoxRenderable, TextRenderable, TabSelectRenderable, ScrollBoxRenderable e os demais renderables do pacote. Sempre devolva o terminal com renderer.destroy(); iniciarTui() já cuida disso para q, Esc e Ctrl+C.

MCP

termfy mcp transforma o processo em um servidor Model Context Protocol sobre stdio. Nada mais é escrito em stdout; diagnósticos vão para stderr.

Configuração no cliente

{
  "mcpServers": {
    "termfy": { "command": "termfy", "args": ["mcp"] }
  }
}

Para o Claude Code: claude mcp add termfy -- termfy mcp. Para desenvolvimento, sem compilar: "command": "bun", "args": ["run", "src/main.ts", "mcp"].

Tools

Tool Entrada Saída
about nenhuma identidade, runtime, plataforma, pasta de dados e créditos
exit_codes nenhuma tabela de códigos de saída
skill topico? (cli, tui, mcp, config, codigos) documentação em Markdown
config_list nenhuma chaves de settings.json em vigor e o esquema
config_get chave valor da chave; isError quando não existe
credentials_status nenhuma arquivo, origem da chave mestra, quantidade e nomes

Nenhuma tool devolve o valor de uma credencial, e nenhuma tool grava. Escrita continua no CLI, onde há confirmação humana.

Resources

URI Conteúdo
termfy://about identidade em JSON
termfy://exit-codes códigos de saída em JSON
termfy://skill documentação completa em Markdown
termfy://skill/{topico} uma seção; o template lista os tópicos

Prompts

Prompt Argumentos Função
operar tarefa instrui o agente a ler skill cli e executar a tarefa pelo CLI com --json

Listar sem iniciar

termfy mcp --list
termfy mcp --list --json

Testar

npx @modelcontextprotocol/inspector termfy mcp

O Inspector abre uma página local para chamar tools, ler resources e inspecionar as mensagens JSON-RPC.

Como adicionar uma tool

  1. Copie template/tool/exemplo.ts para src/mcp/tools/<nome>.ts.
  2. Declare inputSchema com Zod e descreva cada campo com .describe(). A descrição da tool diz quando usar e o que ela devolve.
  3. Devolva content em texto e, quando a saída for estruturada, structuredContent com o mesmo objeto.
  4. Acrescente a tool ao catalogo.tools para que mcp --list a enxergue.
  5. Registre a função em registrarTudo em src/mcp/servidor.ts.
  6. Teste com o Inspector e com bun test.

Nomes de tools usam snake_case. Tools que gravam ou chamam APIs externas precisam dizer isso na descrição e nunca devem ecoar segredos na resposta.

Configuração e credenciais

Tudo que o binário persiste fica em ~/.termfy/:

Arquivo Conteúdo Permissão
settings.json preferências em texto claro 0600
credentials.json envelope AES-256-GCM com os segredos 0600
master.key chave mestra em hexadecimal, criada na primeira gravação 0600

A pasta é criada com 0700. A variável TERMFY_HOME troca a raiz, útil em testes e CI.

settings.json

Chaves em notação de ponto. O esquema do esqueleto:

Chave Tipo Padrão Função
saida.formato texto ou json texto formato padrão da saída do CLI
saida.cores boolean true cores ANSI na saída de texto
tui.abaInicial overview ou about overview aba aberta ao iniciar a TUI
tui.tema noite ou dia noite paleta da TUI
telemetria.ativa boolean false reservado para projetos derivados

Comandos:

termfy config list
termfy config get tui.tema
termfy config set saida.formato json
termfy config unset telemetria.ativa
termfy config path
termfy config schema

Chaves fora do esquema são aceitas como texto. Para que uma chave nova ganhe tipo, padrão e documentação, acrescente-a a ESQUEMA_SETTINGS em src/config/settings.ts.

credentials.json

O arquivo guarda um envelope:

{ "versao": 1, "algoritmo": "aes-256-gcm", "iv": "<base64>", "tag": "<base64>", "dados": "<base64>" }

dados é o JSON { "nome": "valor" } cifrado. Nomes seguem [a-z0-9][a-z0-9_.-]{0,63}, por exemplo openai.api_key ou github.token.

A chave mestra tem 32 bytes e vem, nesta ordem:

  1. da variável TERMFY_MASTER_KEY (64 caracteres hexadecimais);
  2. do arquivo master.key, gerado automaticamente.

Gere uma chave para a variável com openssl rand -hex 32. Quando a variável está definida, master.key é ignorado.

Comandos:

termfy credentials set openai.api_key            # digita sem eco
printf '%s' "$TOKEN" | termfy credentials set github.token --stdin
termfy credentials get openai.api_key            # mascarado
termfy credentials get openai.api_key --reveal   # em claro
termfy credentials list
termfy credentials remove github.token
termfy credentials status
termfy credentials clear --yes

O que a cifra protege

A cifra protege o arquivo contra leitura casual, cópia em backup e varredura do disco por outras ferramentas. Quem tem acesso à mesma conta do sistema consegue ler master.key e decifrar o conteúdo. Para um nível acima, injete a chave por TERMFY_MASTER_KEY a partir de um gerenciador de segredos e não grave master.key em disco.

Usar uma credencial no código

import { obterCredencial } from "../config/credenciais.ts";

const token = obterCredencial("github.token"); // lança ErroApp(4) quando não existe

Nunca escreva o valor em log, em erro, em dados do --json nem em resposta de tool MCP.

Variáveis de ambiente

Variável Efeito
TERMFY_HOME troca ~/.termfy/ por outra pasta
TERMFY_MASTER_KEY chave mestra em hex; dispensa master.key
NO_COLOR desliga cores na saída de texto

Códigos de saída

Zero é sucesso. Cada família de falha tem um número fixo. Scripts e agentes devem tratar o código antes de interpretar a mensagem.

Código Nome Quando
0 SUCESSO operação concluída
1 ERRO_GENERICO falha inesperada sem classificação
2 USO_INVALIDO argumentos, opções ou subcomando inválidos; também quando o binário roda sem argumentos fora de um TTY
3 CONFIGURACAO settings.json ausente, inválido ou chave desconhecida
4 CREDENCIAIS credentials.json ilegível, chave mestra ausente ou credencial não encontrada
5 REDE_OU_API falha de rede ou resposta de API fora do esperado
6 NAO_ENCONTRADO recurso solicitado não existe
7 PERMISSAO permissão negada no sistema de arquivos
8 TERMINAL_INDISPONIVEL a TUI exige um terminal interativo
9 MCP o servidor MCP falhou ao iniciar ou perdeu o transporte
130 INTERROMPIDO entrada cancelada ou processo interrompido com Ctrl+C

A fonte única é src/app/saida.ts. A mesma tabela aparece em --help, em --opencli, na tool MCP exit_codes e na resource termfy://exit-codes.

Em shell

if ! termfy credentials get github.token --json > /tmp/saida.json; then
  case $? in
    4) echo "grave a credencial com: termfy credentials set github.token" ;;
    *) echo "falha: veja /tmp/saida.json" ;;
  esac
fi

No código

import { erro } from "../app/erros.ts";

throw erro.rede("A API respondeu 503.", { status: 503 }); // sai com 5

Para uma família nova, acrescente a constante e a descrição em src/app/saida.ts e um atalho em src/app/erros.ts. Não reutilize números.

Fluxo de execução

  1. main.ts lê argv. Sem argumentos e com TTY, chama executarCli(["tui"]). Sem TTY, imprime a ajuda e sai com 2. Com argumentos, passa adiante.
  2. parser.ts caminha pela árvore do registro, separa opções e argumentos e valida contra as definições. Falhas viram ErroApp(2).
  3. index.ts trata --version, --opencli, --skill e --help. Depois chama executar(ctx) do comando.
  4. O comando devolve { dados, texto }. index.ts imprime texto ou o envelope JSON e devolve o código.
  5. main.ts encerra o processo com esse código.

mcp e tui são comandos como os demais; eles só não devolvem antes de o transporte ou o renderer fechar.

Regras de dependência

  • app/ não importa de nenhuma outra camada.
  • config/ importa só de app/.
  • cli/, mcp/ e tui/ importam de app/ e config/. mcp/ e tui/ podem reutilizar funções de cli/comandos/* que coletam dados (como dadosAbout), nunca o contrário.
  • skill/ importa de cli/registro.ts para gerar a referência.

Build

bun run build compila src/main.ts em dist/<bin> para a plataforma atual com bun build --compile. bun run build:todos gera linux-x64, linux-arm64, darwin-x64, darwin-arm64 e windows-x64. O OpenTUI embute a biblioteca nativa no executável; o docs/ entra como texto; o package.json entra como JSON.

Personalizar o template

Este repositório é um template do GitHub. Para iniciar um binário novo:

  1. No GitHub, clique em Use this template e crie o repositório.

  2. Clone, instale e renomeie:

    bun install
bun run iniciar -- --nome meucli --titulo "Meu CLI" --descricao "O que ele faz." --autor "Sua empresa" --repositorio https://github.com/org/meucli --site https://exemplo.com

    O script reescreve package.json (name, bin, description, bloco termfy), .env.example e as menções a termfy em README.md, AGENTS.md, CHANGELOG.md e .github/workflows/. Os placeholders termfy em docs/ são resolvidos em tempo de execução pelo manifesto, então docs/ não precisa de edição.

  3. Confira: bun run dev -- --version, bun run dev -- --help, bun run dev.

  4. Rode bun run ebook para regenerar o guia em PDF e EPUB com o título novo.

  5. Rode bun run validar.

  6. Apague a seção “Sobre o template” deste README e escreva a do produto.

  7. Faça o primeiro commit e a primeira release conforme release.md.

O que mudar depois

Quer Onde

nova aba template/tela/exemplo.ts → src/tui/telas/, registrar em src/tui/telas/index.ts
nova tool MCP template/tool/exemplo.ts → src/mcp/tools/, registrar em src/mcp/servidor.ts

cores da TUI src/tui/tema.ts

Skills

As skills do framework promovaweb/termfy estão instaladas em .agents/skills/ e registradas em skills-lock.json. Elas ensinam um agente a evoluir o projeto:

Skill Uso
termfy-iniciar criar o binário a partir do template e fazer o primeiro commit
termfy-cli comandos, opções, saída texto/JSON, códigos de saída e OpenCLI
termfy-tui telas, componentes, tema e o visual modern unix
termfy-mcp tools, resources, prompts e testes com o Inspector
termfy-config settings, credenciais, chave mestra e variáveis

Atualize para a versão mais recente do framework com bun run skills:update. Se a pasta sumir, reinstale com bun run skills:instalar. Não edite as skills aqui: mudanças acontecem no framework. Dentro deste repositório, os agentes leem AGENTS.md, que aponta para elas.

Release

Toda alteração publicada sai com versão, changelog, tag e GitHub Release.

  1. Atualize version em package.json (SemVer).
  2. Registre a mudança em CHANGELOG.md, no formato Keep a Changelog.
  3. Se docs/ mudou, avance ebook/VERSION e rode bun run ebook. O PDF e o EPUB em ebook/ entram no commit.
  4. Rode bun run validar.
  5. Commit: release: <bin> vX.Y.Z.
  6. Tag: git tag vX.Y.Z.
  7. Push: git push origin main --tags.
  8. O workflow release.yml compila os binários para linux-x64, linux-arm64, darwin-x64, darwin-arm64 e windows-x64, gera SHA256SUMS e publica a GitHub Release com as notas do changelog, o PDF e o EPUB do guia.
  9. Confira a release em https://github.com/<org>/<repo>/releases/tag/vX.Y.Z.

Uma tag publicada nunca é movida. Correção posterior recebe nova versão.

Build local

bun run build          # dist/<bin> para a plataforma atual
bun run build:todos    # dist/<bin>-<plataforma> para todas
./dist/<bin> --version

Ebook do guia

bun run ebook          # ebook/<Titulo>-Guia-do-Usuario-v<versão>.{pdf,epub}
bun run ebook:verify   # confere sem gerar; entra em bun run validar

A fonte é a própria docs/, com os placeholders resolvidos pelo manifesto. Depois de bun run iniciar, regenere o ebook para a capa e o rodapé levarem o título novo. Requer Pandoc, WeasyPrint, ImageMagick, xmllint, poppler-utils e unzip.
